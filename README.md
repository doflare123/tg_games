# TG Games

Отдельный игровой бот и Mini App для Telegram Serverless. Исходники на TypeScript, strict, без `any`. Игровые ядра, серверные правила, хранилище, платформа и интерфейс разделены.

В каталоге доступны Тетрис и Сапёр. Doom и Mario временно скрыты из интерфейса, прямых запусков и меню команд; их адаптеры сохранены в исходниках.

## Что работает локально

- Сапёр: 9×9 / 10 мин, 16×16 / 40 мин, 30×16 / 99 мин; безопасное первое открытие с соседями, флаги, открытие соседей по числу и отдельные рейтинги времени для каждого размера (всё время / неделя UTC). Лучшее время победы каждого игрока; меньше — лучше.
- Рейтинговый Сапёр: скрытое поле хранится на сервере, клиент получает только открытые клетки; сервер проверяет каждый ход и измеряет время от первого открытия до победы. Ходы сохраняются с compare-and-swap и повторяются идемпотентно. Свободная игра выполняется целиком в браузере. Компьютер: ЛКМ — открыть, ПКМ или F — поставить/убрать флаг. Телефон: тап — открыть, удержание 0,5 с — поставить/убрать флаг; движение пальца отменяет удержание и позволяет прокручивать большие поля. Флаги доступны до первого открытия и не запускают таймер. Лимит партии — 60 минут, сворачивание не останавливает таймер; перезагрузка страницы начинает новую попытку. Доступен запуск `/game_minesweeper`. Рейтинги Сапёра общие, групповые уведомления относятся к Тетрису. Для публикации новой игры потребуется отдельное применение схемы `minesweeper_runs`; сборка и тесты live-БД не меняют.
- Tetris: Marathon, Sprint 40 lines, Ultra 120 seconds; seven-bag, повороты с wall kicks, hold, ghost, lock delay, уровни, combo/back-to-back, T-spin, perfect clear, звук, клавиатура и multi-touch.
- Жесты на поле Тетриса: тап, движение свайпом, удержание для ускорения и быстрый сброс вниз; отдельный HOLD и клавиатура.
- Обычные сохранения и восстановление незавершённой рейтинговой партии на устройстве.
- Авторитетная проверка Tetris общим игровым ядром по записи действий. Сервер не принимает готовые очки клиента.
- Лучший результат каждого игрока, общий и групповые топы, неделя UTC, собственная позиция за пределами топ-50. В новой группе появляются и прежние рекорды её подтверждённых участников; без повторного внесения партий и старых объявлений.
- NES-адаптер JSNES: собственный ROM, звук, клавиатура/тач/геймпад, сохранения с привязкой к SHA-256 ROM.
- Doom: изолированный Emscripten/WASM-адаптер, собственный IWAD, управление и сохранения на устройстве. Движок собирается отдельно.
- Telegram endpoints, обработчик команд бота, SQL-схема и сборка под ограничения Serverless.

Рейтинги Mario/Doom пока выключены: серверные verifier для этих движков ещё не реализованы. Сезоны — следующий этап. Развёртывание и лимиты реального Telegram Serverless требуют проверки на новом боте; локальные тесты этого не заменяют.

## Группы и управление

В Doom и Mario стоят стандартные мобильные стики nipplejs. Добавлены прямые команды, общий/групповой рейтинг и админская настройка объявлений топ-10. [Правила доступа, команды и объявления](docs/groups-and-controls.md). Минутное удаление и внешний worker отложены; используются только нативные ephemeral-команды и ответы.

## Запуск

Нужны Node 24+ и npm.

```sh
npm ci
npm run dev
```

Открыть адрес Vite. Только в dev работает локальный API с фиксированным тестовым пользователем и отдельной SQLite `.cache/arcade-dev.sqlite` и явно обозначенной локальной тестовой группой. Этот API не входит в production bundle. За пределами Telegram production-сборка позволяет свободную игру; рейтинги требуют Telegram.

```sh
npm run check       # strict types, lint, tests, client + cloud build
npm run test:browser
```

Для браузерной проверки сначала установить Chromium в `.cache/playwright`:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH=(Join-Path (Get-Location) '.cache/playwright')
npx playwright install chromium
```

## Сборка Doom

```sh
npm run setup:doom
npm run build:doom
npm run build
```

Первая команда скачивает переносимый Emscripten 4.0.20 и исходники doomgeneric в `.cache/`; потребуется около 1 ГБ для загрузки и больше для распаковки. Системные настройки не меняются. Исходники doomgeneric закреплены на commit `e257a09527062bfb986b6e5e0780839b6cbd5b71`. Сборка не включает игровой WAD. Для Mario/Doom игрок выбирает собственные файлы; они не отправляются на сервер. Музыкальные MIDI-патчи не входят в сборку; эффекты звука собираются через SDL_mixer.

Для полной проверки Doom нужен IWAD; браузерный smoke-test автоматически использует Freedoom 0.13.0, если он распакован в `.cache/freedoom/freedoom-0.13.0/`. Тестовый NES ROM генерируется программно и не содержит данных Mario.

## Развёртывание нового бота

1. Создать отдельного бота в BotFather и включить Serverless.
2. `npm run cloud:login` — CLI access token вводится интерактивно; это не Bot API token. Секрет не добавляется в исходники или frontend env.
3. `npm run check`, затем `npm run deploy`. Build ничего не публикует; deploy публикует код и статические файлы.
4. `npm run cloud:migrate` — отдельно просмотреть и применить схему БД. Между deploy и первой миграцией API ещё не готов к игровым запросам.
5. Сверить публичный URL из `npm run cloud:status` с `src/server/platform/mini-app-config.ts`. Выполнить `npm run configure:bot` для регистрации ephemeral-меню. В BotFather: `/mybots` → бот → Bot Settings → Configure Mini App → Enable Mini App; указать URL из CLI (для этого бота `https://app8745166402.tgcloud.ai/`). Именно Main Mini App нужен для групповых ссылок `?startapp`, одной публикации статики недостаточно.
6. Добавить бота администратором группы. Это нужно для проверки участия и приватных ответов на обычные текстовые команды. До назначения администратором при Privacy Mode обычная команда без `@имя_бота` может не доставляться; используйте зарегистрированное ephemeral-меню или `/game_tetris@имя_бота`.
7. `npm run diagnose:bot` — read-only проверка Main Mini App, меню и прав в первых 10 известных группах. Не отправляет сообщения, не меняет настройки и данные.
8. Проверить на Android/iOS/Desktop: `/start`, открытие, авторизацию, партию, повтор запроса и рейтинг. Endpoint `probeRuntime` проверяет доступность WASM/crypto на сервере без запуска тяжёлой симуляции.

Команды нового бота: `/start`, `/games`, `/help`, `/top`, `/game_doom`, `/game_mario`, `/game_tetris`, `/game_top`, `/game_notify_on`, `/game_notify_off`. В личке используется `web_app`-кнопка с HTTPS URL хостинга, работающая без Main Mini App. В группе после включения Main Mini App используется URL-кнопка с прямым `startapp`; до включения — переход в личку через `start`, сохраняющий выбранную игру. Отдельный доступ к чужим группам из ссылки не выдаётся.

## Структура

```text
src/games/tetris/           чистое детерминированное ядро
src/shared/                 контракты, ошибки, runtime-валидация
src/server/domain/          сессии, правила, порт хранилища
src/server/platform/        SQL-адаптер, Telegram context и SDK boundary
src/server/endpoints/       короткие входные точки Mini App
src/server/handlers/        Telegram updates
src/client/platform/        API, SDK Telegram, IndexedDB
src/client/games/            независимые игровые адаптеры
src/client/ui/               общие элементы интерфейса
scripts/                    сборка, dev API, browser checks
tests/                      ядро, SQL и серверные сценарии
```

`npm run build` генерирует `tgcloud/schema.js`, `tgcloud/endpoints/`, `tgcloud/handlers/`, `tgcloud/lib/` и `dist/client/`. В generated-каталогах исходники не редактируют. Build запрещает Node/Bun imports и внешние runtime-зависимости в cloud modules. DOM и Node API не входят в игровое ядро.

## Результаты и ограничения

Каждый ranked-run привязан к проверенному Telegram user id и неизменяемому ruleset. Чанк ограничен 600 ticks; действуют проверка порядка, лимит действий на кадр и проверка серверного времени. Checkpoint обновляется SQL compare-and-swap. Повтор идентичного последнего чанка идемпотентен; конкурентное обновление даёт конфликт. Последний принятый чанк хранится атомарно вместе с checkpoint, предыдущие архивируются перед следующим обновлением.

Пауза/сворачивание во время игры переводят текущую рейтинговую попытку в свободную; завершённая попытка, ожидающая подтверждения сервера, сохраняется и продолжает отправку. Тип партии постоянно виден над полем. Закрытие игрового экрана сохраняет незавершённую попытку для восстановления. Рейтинговые снимки дополнительно сохраняются по id партии, финальный снимок записывается сразу. Синхронизация использует фиксированную цель одного запуска и не догоняет меняющийся кадр в цикле. Хранилище браузера best-effort: его очистка удаляет локальную несинхронизированную запись. Старты ограничиваются по частоте; этот лимит не является строгой финансовой квотой при конкурентных запросах.

Проверка replay подтверждает допустимость результата по правилам, но не отсутствие TAS/ботов. Длительность и цены вызовов, DB quota, пропускная способность и поведение реальной платформы не измерялись без подключения бота. Встроенные ambient-типы SDK описывают только используемую документированную поверхность; это не полный официальный TypeScript SDK.

Зависимости зафиксированы в package-lock.json. JSNES — Apache-2.0; doomgeneric — GPL-2.0, лицензия копируется рядом с собранным движком. Условия игровых данных рассматриваются отдельно от лицензий движков.
