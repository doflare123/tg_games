# Freedoom: первый эпизод

Текущая публикация — закрытый тест для владельца (Telegram ID `930852883`). Остальным пользователям скрыты карточка и таблица, а все шесть игровых API возвращают отказ до доступа к записи. Проверяется ID из подтверждённого Telegram-контекста. Групповые объявления Freedoom на время закрытого теста подавлены. Остальные аркады работают как прежде. Статические файлы движка и свободного IWAD не являются секретными ресурсами; ограничены запуск через приложение, прогресс и рейтинги.

В каталоге и по `/game_doom` доступен Freedoom 0.13.0, Phase 1, первый эпизод. Игроку не нужны WAD или файлы сохранений: закреплённый `freedoom1.wad` загружается с нашего статического хостинга. SHA-256 проверяется в браузере и на сервере. Данные игры и скомпилированные движки исключены из Git.

## Правила результатов

Один забег даёт независимые результаты для E1M1–E1M9 и всего эпизода. Завершённые карты попадают в таблицы, даже если игрок затем не закончит эпизод. Четыре сложности не смешиваются. Категория «На скорость» требует выхода с карты; «100%» дополнительно требует всех монстров и секретов. Для 100% эпизода нужны все девять карт, включая секретную. При обычном прохождении секретная карта необязательна.

Это результаты карт внутри кампании: оружие и здоровье переходят между уровнями. Отдельные таблицы для старта с пистолетом не заявлены. Эпизод начинается с E1M1 и заканчивается выходом из E1M8; секретный маршрут воспроизводит сам движок.

Время считается по активным игровым тактам, 35 Гц. Межуровневые экраны исключены. Смерть и повтор карты не обнуляют время этой карты или эпизода. Лучший результат каждого игрока определяется минимальным временем; при равенстве выигрывают более ранний старт и ID результата. Доступны общие и групповые таблицы за всё время и неделю с понедельника UTC; период определяется началом забега.

## Автосохранение и продолжение

Каждую секунду iframe отдаёт запись команд родительскому интерфейсу; браузер сохраняет её в IndexedDB. Примерно раз в пять секунд запись уходит на сервер частями не более 350 тактов. В SQL команды, границы перерывов и курсор приёма обновляются одним условным UPDATE. Перед отправкой клиент сохраняет неизменяемый запрос: при потерянном ответе повторяется тот же фрагмент, даже если игра уже записала новые команды. Чужая партия, другой повтор, слишком большой фрагмент или запись, опережающая серверное время, отклоняются.

Кнопка продолжения получает серверную запись, подхватывает совместимый локальный хвост и быстро воспроизводит её до места остановки. Пользователь не выбирает и не загружает файлы сохранений. При смене устройства доступен последний принятый сервером фрагмент; при аварийном закрытии возможна потеря последней секунды локальной записи или неотправленного хвоста, если локальное хранилище недоступно.

Пауза, скрытие приложения, продолжение сохранённой игры и длинный разрыв кадров выключают рейтинг всего эпизода. Текущая карта с перерывом также не засчитывается; следующие карты, пройденные целиком, могут дать рекорд. Сервер хранит границы перерывов и проверяет их при публикации. Пауза не останавливает возможность играть дальше. Ограничения первой версии: до двух часов игровых тактов на забег, семь дней на отправку записи.

## Проверка без ожидания в игровом цикле

Сервер принимает только команды управления. Время, выходы, монстры, секреты и финал извлекаются из независимого воспроизведения закреплённого движка. Клиентские память, сохранения и заявленные результаты не принимаются. Интерфейс приёма записи не запускает симуляцию.

`verifyDoomRun` вызывается отдельно, примерно каждые 20 секунд и на финише. Пока ответ задерживается или отсутствует, локальные игровые такты продолжаются. До успешного воспроизведения результатов в рейтинге нет. Проверка получает отдельный экземпляр WASM без SDL, звука и отрисовки. Первый вариант перепроверяет принятый префикс с начала; запись ограничена двумя часами. SQL lease и задержка повтора защищают очередь от параллельных повторов. Публикация каждого результата идемпотентна, курсор проверки не регрессирует.

Очередь остаётся в SQL после закрытия браузера. Существующий служебный `maintenance` обрабатывает один ожидающий Doom-забег за вызов; нового постоянно работающего демона или расписания эта поставка не создаёт. Без последующего запроса проверки или вызова maintenance закрытый забег останется в очереди. Обычные игровые запросы других аркад тяжёлую проверку Doom не запускают.

Рекорды подключены к общей `social_jobs`: первый рекорд/улучшение лидера/обгон в топ-10, актуальное членство, настройки и тема группы, повтор доставки, детерминированные ID и общий пятиминутный лимит объявлений для всех игр. Несколько рекордов карт из одного забега ждут общей очереди. Выключение уведомлений или вытеснение рекорда подавляет ожидающее сообщение. Блокировка рейтинга исключает игрока из таблиц и новых результатов.

## Подготовка локальной сборки

```sh
npm run setup:doom
npm run setup:freedoom
npm run build:doom:ranked
npm run check
npm run test:doom:browser
```

`setup:freedoom` использует закреплённый [официальный релиз 0.13.0](https://github.com/freedoom/freedoom/releases/tag/v0.13.0), проверяет архив и IWAD и извлекает только известные файлы внутри `.cache`. `build:doom:ranked` не изменяет upstream checkout: патчи применяются в `.cache/doom-ranked`. Основа — doomgeneric `e257a09527062bfb986b6e5e0780839b6cbd5b71`, Emscripten 4.0.20. В `public/engines/doom` появляются браузерный движок, автономный headless verifier, WAD, лицензии, manifest и архив соответствующих исходников `source.tar.gz` с командами пересборки. MIDI-инструменты пока не поставляются, эффекты звука собираются через SDL_mixer. Физика работает с фиксированными командами; меню читов, сохранений, загрузок и смены карты недоступны.

Игровые данные не входят в исполняемые серверные модули. Ранний вариант с WAD внутри модулей сломал реальные вызовы профиля и рейтингов, хотя management runner принимал ту же сборку. Данные перенесены в отдельную таблицу `doom_assets`; манифест активируется после загрузки всех 40 частей сжатого IWAD. Сервер читает небольшие части, распаковывает их через `fflate` и проверяет SHA-256 через `@noble/hashes`; внешний HTTP-запрос не нужен. Для серверного кода установлены проектный бюджет 2 МиБ суммарно и проверка платформенного лимита 1 МиБ на модуль. Обычные игровые API не импортируют движок и не читают IWAD.

Отдельная операторская установка данных: `node --use-env-proxy --experimental-transform-types scripts/install-doom-data.ts` показывает план, вариант `--apply` создаёт только таблицу ресурсов и дописывает закреплённые данные, отказываясь перезаписывать отличающиеся записи. Этот скрипт не входит в build/test и не меняет профили, игровые партии или результаты. WAD и все сборочные артефакты исключены из Git.

Без собранного verifier или WAD основной проект по-прежнему проходит обычную сборку; серверная проверка Doom отвечает «недоступно» и не публикует непроверенные результаты. Для запуска Freedoom нужны все перечисленные игровые артефакты. Production-схема описана в `schema.ts`; build/test не публикуют код и не мигрируют живую базу. Для закрытой публикации отдельно применены только две новые таблицы Freedoom; существующие данные и индексы сохранены.

## Проверено и что ещё требует проверки

Проверены strict TypeScript, отдельная конфигурация без DOM/Node для сервера, SQLite, владение партией, валидация и повторы, восстановление записи после пересоздания сервиса, разделение таблиц, исключение перерывов и обработка групповых уведомлений. Проверен настоящий WASM verifier: выходы с восьми обычных и секретной карты на небольших синтетических картах, добавленных к локальному IWAD; исходные игровые данные в тестах не коммитятся.

Chromium проверяет запуск настоящего Freedoom без файлового ввода, сохранение/продолжение, задержанный ответ проверки при продолжающейся игре и мобильную ширину 390 px. Отдельно сравниваются состояния браузерной SDL-сборки и серверной сборки, включая такты, карту, координаты, здоровье, RNG и все результаты синтетического эпизода.

В реальном Telegram Serverless подтверждены инициализация WASM, чтение IWAD из отдельной таблицы, распаковка и SHA-256, независимое воспроизведение 350 тактов, чтение прогресса/таблицы владельцем, отказ всем шести API для постороннего ID даже с поддельными полями владельца в запросе и разделение каталога владельца/гостя. Дополнительно проверены `getProfile` и обычный рейтинг Тетриса; пользователь подтвердил восстановление имени и рейтингов в реальном Telegram после исправления. Проверочный вызов занял около 0,76 секунды по измерению платформы; это не замер длинной кампании или нагрузки. Опубликованный сайт проверен в Chromium: остальные игры доступны, карточка Freedoom скрыта, прямой гостевой маршрут не запускает iframe. Для повторной проверки сборки в облаке предусмотрен отдельный скрипт `node --use-env-proxy --experimental-transform-types scripts/doom-cloud-check.ts`; он не входит в build/test, не публикуется и не создаёт партии или рекорды. Проверка профиля использует обычный путь с аналитикой посещения и обработкой общей очереди уведомлений.

Полный живой эпизод с реальными боями, длинные серверные записи, нагрузка и целевые мобильные Telegram WebView ещё требуют проверки. При отсутствии нужных возможностей результаты остаются ожидающими проверки.
